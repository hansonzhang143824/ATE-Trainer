# 工作流全景（单一入口）

> **一句话**：Offline Coding = Part1 DFT(测试意图) + Part2 原理图(连接关系) + Part3 机台手册(API 规则) + Part4 工程师经验 → 可被机台软件编译通过的 VS 工程。
> **本文件是唯一入口**：流程地图 + 文件所有权 + 更新协议都在这里。细节见文末「文档索引」。
> **更新规则**：流程/文件/所有权变化时，同步本文件（+ 对应细节文档）。
> **四层**：主 pipeline / 旁路 / 自进化 / 知识层。

---

## 一、全景图（四层）

```
用户: "写 TMxxx" / "生成代码"
   │
   ▼
主 Pipeline（codegen）: 入口解析指令 → Step0 原理图解析(有货先验) → Step1 DFT 解析+pin 交叉校验 → CBIT-Definition → 共用循环 → 收尾双查
旁路（用户触发）:       sch-parse / compile / deploy / testplan
自进化（/evolve）:      rules / experience / sub-function（共享 daylog）
知识层（四层分层）:     L0 sources · L1 rules-registry · L2 experience+shared_functions · 参考 references
```

## 二、工作流地图（环节表）

> 列：环节 / 所需内容 / 依赖资料（文件）/ 产出 / 负责人·状态。
> 负责人：**脚本** = 已脚本化（固定逻辑）；**agent** = 推理密集保留 agent；**用户** = 你提供/拍板。

### 主 Pipeline（codegen，唯一解析链）

| 环节 | 所需内容 | 依赖资料 | 产出 | 负责人·状态 |
|------|---------|---------|------|------------|
| Step0 原理图解析（有货先验） | **前置 · 工程完整性门** `check_library_files.py`（Library 16 文件 + .treg，缺失反馈用户）→ 检测无 SCH-Connect-Map → sch-parse | `Dali-SCH.csv` | Component-Statistic + **SCH-Connect-Map**（全局产物，可旁路单跑） | **脚本** `sch_parse.py` |
| Step1 DFT 解析 + pin 交叉校验 | dft-parse → meta/YAML；**`check_dft_pins.py` 三源三层校验**（L1 DUT pad / L2 测试 pad 角色 / L3 组合节点抽象，未命中 → 问用户） | DFT + `Pin_Channel_define.h` + SCH-Connect-Map | `test_conditions.yaml`（DFT 解读层）+ meta + **pin 校验报告（0 未命中才放行）** | **脚本** `gen_testitems_meta.py` + `gen_test_conditions.py` + `check_dft_pins.py` + agent |
| Step2 CBIT-Definition（公共前置 · 每次进入必走） | CBIT 表 + 定义文件 | `CBIT表-DALI.xlsx` + SCH-Connect-Map + 工程 dll `F12011.dll` | 三类继电器 #define 全落 **StdAfx.h**（单点 / PATH_RELAY / RELAY_ROLE）；判定门：有定义+dll>1天→才 check（V6 F/S 合并三重门：端别×电气可达×收敛，需 --map）、≤1天→跳过；无→四阶段创建 | **脚本** `gen_cbit_defines.py` / `gen_paths.py` / `gen_path_defines.py` / `gen_relay_role_defines.py` |
| Step3 框架创建（批次级） | 本批 TM 一次性按 **7 类项目结构类型**分类（按序命中即停；2~6 类框架待确认）→ 有框架的按 testType 选模板——**本环节 = testType 类型判定权威点（唯一）** | **`test_conditions.yaml`（testType 权威）** + `framework.md` | 函数骨架（普通/Toggle-AWG/Trim） | 模板 |
| Step4 继电器闭合 | **材料门前置**（`verify_material_receipt.py`，无可参考案例 → FAIL 拦截）+ 通路 + 功能规则 | `relays.md` + `relay-check.md` + StdAfx.h（命名权威） | `cbite.SetOn(Kxx,Kyy,-1)+delay_ms(3)` + pin-map JSON 副产物 | agent（relay-agent） |
| Step5 上电 | meta + pin-map | `power-sequence.md` + R-PON | 上电代码 + PowerState | **脚本** `gen_power_sequence.py` |
| Step6 寄存器配置 | registermap / 同名 .sv | `register-config.md` + reg_config/*.sv | `I2CWriteSameData()` | 模板 + agent |
| Step7 测量 | 测试类型 + 参数 | `measurement.md` + `functions-registry.md` | MI/MV/Toggle/Trim 测量 | agent |
| Step8 下电 | PowerState | `power-sequence.md` + R-POFF | 下电代码 | **脚本** `gen_power_sequence.py` |
| Step9 LogData | params + 单位规则 | `units.md` + R-LOG/R-HYS/R-VIR | SetTestResult | 模板 |
| Step10 收尾双查 | 完整代码 + meta（循环内逐 TM 已过 **`verify_single_fn.py` 冒烟 7 项，FAIL 停留当前 TM**） | `check_testitems_meta.py --require-all --require-scope <本批>`（**meta 双向强制**：无 OVERVIEW 记录 → ERROR、本批 isCodeGen='Y' 漏项 → FAIL 列出 TM）+ `verify_relay_trace.py --meta --warn-as-error` + `verify_awg_params.py` + `gen_cbit_defines.py --verify` + `fast_rebuild.ps1` | PASS/FAIL 报告（FAIL → 修复 → 重查 → 直到 PASS） | **脚本**（门禁） + check-agent 60+ 项 |

## 四、更新协议（四模板 + 三注册表 + 审计 + 无缝接入）

### 四输入协议（你给我的四类东西，各一个模板）

| 类型 | 模板要点 | 落地 |
|------|---------|------|
| 规则/铁律 | `【类型】规则\|【一句话】\|【来源】\|【适用范围】\|【能否机器判定】\|【正文】` | → rules-registry（能机判→同步 verify 脚本） |
| 参考材料 | `【类型】代码案例\|芯片 Block\|测试方法\|电路\|手册 · 【名称】·【文件】·【对应】·【一句话用途】·【提炼要求】` | → references/ 归档 + index.md 登记 |
| Library-Functions | `【类型】新增\|改签名\|改语义\|弃用 · 【函数名】·【库】·【签名】·【触发场景】·【调用语义】·【调用点】·【影响面】` | → functions-registry + 影响面检查 |
| 经验 | 六类判定（global/specialized/project/temp/not useful） | → experience/ + rules-registry 分类 |

|--------|--------|:---:|

### 无缝接入机制

- **git diff 检测变更**：新资料/改规则进库，靠 diff 而非传话。
- **完整性审计脚本** `gen_knowledge_audit.py`：ID 连续/无重复、active 有强制层、反向引用（agent/脚本引用的 ID 能查到）、来源清单对照（手册"已提炼/未提炼"）。→ ⏳ 待建（执行顺序第 5 步）。
- **codegen 开始读 param_type_index**：生成代码前查 references/param_type_index + functions-registry。
