循环关系

执行一次 每次进入必走 逐 TM · 循环 每批 / 收尾 低频 用户触发 ◇ 门禁（FAIL 停留）
① 主流程总览 · 门禁 G0~G5 · 绿 = PASS 前进 / 红 = FAIL 回流

怎么读：每测一项走一圈 G0 → … → G1（绿色箭头）；G1 FAIL → 停留当前 TM 修正，PASS · 非最后一个 → 沿绿线回 G0（下一条），最后一个 → 进 Step5。收尾每批一次：G2 编译门 → G3 Toggle 3 参数 → G4 继电器轨迹 → G5 meta 全覆盖，任一 FAIL 沿红线回「修复 → 重新检查」直到 PASS。批量纪律 B-001：先插 1 个代表函数 → 编译 + meta + relay 全绿 → 再放量所有 TM。收尾另有 verify_bst_sw_sequence.py（台阶黄金约束）与各 gen_* --audit-rules（脚本规则自检 13/11/12/19）。

② 全链路数据流（文件 × 脚本 × 产物 · 每步输入输出）

读：左列脚本链按执行顺序排列（Step0 → Step1 → Step2 → Step4/5），每个框 = 脚本 · 输入 → 产物；右列 = 终产物及其被谁消费。原理图 / DFT 有变 → 沿橙色虚线回顶部整链重跑（六门控任一 FAIL 即停）；主 pipeline 每测一项只读不重建（有货先验）。SCH-Connect-Map 的生成归 sch-parse，不脚本化。

③ 知识回流环（daylog → /evolve → codegen，收尾沉淀）

读：每次收尾必写 daylog + PROGRESS + auto-memory → 用户触发 /evolve 三 agent 提炼 → 入 L1 rules-registry（强制） / L2 experience + shared_functions（复用） → codegen 生成前先查引用；规则修正后沿橙色线同步 skill / knowledge / check-agent 闭环。

铁律要点：单函数冒烟 FAIL 停留当前 TM（B-001 脚本强制）；收尾双查 FAIL→修复→重查→PASS；meta 全覆盖门 每批必做（双向：无 OVERVIEW→ERROR、本批 isCodeGen=Y 未写→FAIL 列 TM）；写码两段式 先正确（追加尾部+编译）后归位（按 TM 编号，最小单位=单个 TM 单元）再增量编译；CBIT-Definition 每次进入必走；脚本改动后必跑 --audit-rules（13/11/12/19 规则覆盖自检）。
