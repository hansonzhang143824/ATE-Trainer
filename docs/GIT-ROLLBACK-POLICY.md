# Git 回滚策略

从本文件生效起，每一个开发任务都必须留下可回滚的 Git 检查点。

## 任务开始

1. 记录当前分支、HEAD、工作区状态和正在使用的 worktree。
2. 如果工作区干净，创建任务分支或任务起始 commit。
3. 如果工作区已有改动，不覆盖或混入这些改动；先建立基线清单，必要时使用独立 worktree 或补丁文件隔离本任务。

## 任务结束

1. 只提交本任务产生的代码、配置、文档和测试。
2. 运行与改动相关的验证，并把结果写入提交说明或任务记录。
3. 提交后确认 `git status` 没有本任务遗留的未提交改动。
4. 在交付消息中报告分支、完整 commit hash、验证命令和结果。

## 运行产物

运行日志、训练材料和大体积生成物不默认全部提交。它们必须保留 run ID、路径、SHA-256 和生成时间；如果它们影响复现，则连同对应清单或不可变快照一起提交。

## 无法提交时

如果 Git 元数据目录不可写，不能声称任务已经完成 Git 保存。应先把精确文件树复制到 `recovery/<任务标识>/`，生成包含时间、来源、文件大小和 SHA-256 的 manifest，再说明 Git 提交受限的具体原因，直到可以创建真正的 commit。
