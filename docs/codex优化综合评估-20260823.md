## 四、codex 做错的 / 有风险的（待你决定）

### 4.1 relay / measure 生成断层（最重要，需你拍板）

- codex 5 个 agent（orchestrator / hardware-topology-reviewer / test-design-reviewer / verification-build-reviewer / knowledge-curator）**全是 reviewer，没有 relay-agent 和 measure-agent 的执行生成角色**。

- **三种处理选项**（见优化建议清单 Q1）。

### 4.2 V2 skill 文档空壳（采纳 V2 后必须补）

- 即便采纳 V2，其 skill 文档全是空壳：SKILL.md(3行) / PATH_CONTRACT.md(3行) / VALIDATION_RULES.md(3行) / RELAY_CONTROL_RULES.md(2行) / AI_CONTEXT.md(4行)。
- 后果：下次换人/换 AI 无法从文档重建 V2 规则（25 列契约、PathProof 规则、Kelvin 匹配），可复现性差。
- **建议**：把 csv_schematic_adapter_v2 的 25 列契约、csv_pathproof_v2 的 PathProof/Kelvin 规则写成正文，V2 才算真正沉淀。

### 4.3 `publish_codegen_samples_to_vs.py` 用 `#if 0`（119 行）

- 用 `#if 0` 包裹旧函数注入 `CODEX_OFFLINE_ORIGINAL` 僵尸块，与自报"`#if 0`: 0"矛盾。
- **建议**：若保留"样本发布"能力，改显式备份 + 原子替换，禁用 `#if 0`。

### 4.4 `verify_library_status.py` 逻辑缺陷（72 行）

- `stub_methods()` 检测到 TODO/恒成功桩函数后**只 `print`、不进 `errors`**；`errors` 仅"正式工程引用 sub_func.h"一种来源。
- 后果：声称"阻止 TODO 桩函数进正式工程"，实际检测到也只打印、照常 PASS。
- **建议**：stub 命中进 errors 导致 FAIL，或改名降级为"仅报告"。

### 4.5 `verify_bst_sw_sequence.py` 硬编码脆弱（150 行）

- `TARGETS` 硬编码 3 函数名；字符串 index/count 匹配，依赖 `\r\n` 精确字节。一次性回归可用，不可泛化。
- **建议**：标注"一次性回归"归档，或参数化 TARGETS 与黄金序列。

### 4.6 报告只报最终态、回避过程态

- 多处写"未使用 `#if 0`"，但 Backup 证明用过（后清理）。验收应"最终态 + 过程备份"双看。
