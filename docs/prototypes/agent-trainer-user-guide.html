●

!

1. 第一次使用：先做这 6 步

  1. 打开正式入口；刚重启服务时先刷新。
  2. 顶部切到训练模式，执行范围保持 SMOKE_ONLY。
  3. 看左侧 AGENTS 和 WORKFLOWS。空项目应为 0/0；已有候选时只显示当前项目登记内容。
  4. 点击“新建 Agent”，再点击“新建工作流”把它放进去。
  5. 点击运行，等待状态变为 completed。
  6. 看运行记录，确认输出、revision、步骤状态和 scope，再决定是否优化或发布。
✓能看到模式切换、Agent 列表、工作流列表、运行和保存按钮。
✓第一次实验始终从训练模式开始。

2. 系统介绍与架构

Agent Trainer 是“定义 Agent → 编排工作流 → 用真实 fresh child 执行 → 留下运行证据 → 冻结并发布 → 工程模式回放”的训练和发布工作台。Agent 是独立执行单元；工作流是有序步骤；候选、冻结快照、发布版本是逐级边界。

A

Agent

有 ID、职责、输入/输出 schema，可绑定 Skill 或脚本。

W

Workflow

按顺序引用 Agent；步骤顺序决定执行顺序，绑定决定交接内容。

R

Revision / Release

候选可改，冻结不可变，发布后工程模式只读回放。

3. 三种模式

模式可以做什么不能做什么
训练模式创建/修改候选，打开原生会话，运行 smoke，保存和冻结。不能把未验证候选当成工程版本。
发布模式审核 run、快照、版本和 SHA-256，发布 smoke。候选只读，不能运行或修改。
工程模式查看并运行已激活发布版本。不能编辑、替换步骤或调用未发布候选。

4. 创建一个 Agent

  1. 训练模式点击左侧 ＋ 新建 Agent。
  2. 使用稳定 ID，例如 agent-demo-1；避免历史专家 ID。
  3. 填写名称和职责，明确它做什么、不做什么。
  4. 填写输入/输出 schema，字段名、类型和必填约束要明确。
  5. 确实需要时再添加 Skill、脚本、依赖或权限。
  6. 点击保存候选，确认 candidate revision 变化。

最小示例

Agent ID: agent-demo-1
职责：回答简单算术问题。
输入：{"question":"1+2"}
输出：{"answer":3}
约束：只返回 JSON。

当前八专家 smoke 合同的固定输入是：

1+2等于几，把答案写在JSON里
✓列表有新 Agent，Inspector 显示自己的 ID/版本。
✓保存后出现新 candidate revision。
✓Agent 可以加入工作流，工作流引用 Agent ID。

5. 优化一个 Agent

  1. 选择 Agent，记下当前 revision 和最近一次通过的 run。
  2. 点击打开当前 Agent 原生会话，确认 preset 为 agent-trainer。
  3. 先读取 trainer_context、trainer_assets，再说明要改什么。
  4. 用 trainer_apply_changes 写入候选，使用 trainer_validate 校验。
  5. 回白色页面确认 revision/change set 变化，再运行新 revision。
  6. 比较前后输入、输出、状态、绑定和哈希。

可复制的优化指令

请优化当前 Agent：
1. 读取 trainer_context 和 trainer_assets；
2. 保留 question 输入和 answer:number 输出；
3. 规则改成“只返回 JSON，不输出解释”；
4. 用 trainer_apply_changes 写入候选；
5. 用 trainer_validate 校验并返回新的 revision。

边界 不要直接用 PowerShell 改候选文件替代 Trainer 变更；那会破坏 revision、change set 和 run 追溯。

6. 创建工作流

  1. 训练模式点击 ＋ 新建工作流。
  2. 当前 Agent 会成为第一步；选择其他 Agent 后点＋ 加入当前 Agent。
  3. 用上移/下移调整顺序，用删除移除步骤。
  4. 设置 input/output binding：只有声明的输出才传给下一步，原始输出仍在证据里。
  5. 保存候选，确认 workflow revision 变化，再运行。

例子：T3 → T1 → T2

步骤 1 · T3输出 7
→
步骤 2 · T1输出 3
→
步骤 3 · T2输出 5

验收重点是系统按页面顺序派发、每步收到声明输入并写入输出；每个 smoke child 仍必须返回 {"answer":3}。

7. 优化工作流

  1. 先记录当前步骤顺序、绑定和最近 run。
  2. 训练模式中增加、删除或上下移动步骤。
  3. 出现“下一步没有输入”时，检查上一步 output binding 和下一步 input binding 是否同字段。
  4. 保存新 revision，运行并比较步骤数、步骤 ID、每步输入/输出、状态和耗时。
  5. 通过后才冻结发布；不通过就继续改候选。

推荐顺序

先修步骤顺序，再修绑定，最后优化 Agent 内部说明。

通过信号

新 run 使用新 workflow revision，发布后仍能复现同一顺序。

8. 用聊天训练 Agent

普通聊天只产生回答；只有在 Trainer 原生会话中实际调用 Trainer 工具，才会产生候选变更。不要把“模型说改好了”当成真实修改。

聊天方式是否改变候选确认方法
普通聊天不会没有新 revision/change set/run。
Agent Trainer 原生会话可以preset 为 agent-trainer，出现 apply_changes 记录。
工作流训练会话可以回白色页面查看 workflow revision 和验证 run。

创建模板

请在当前 agent-trainer 项目创建 agent-demo-1：
职责是回答简单算术；输入 question:string；输出 answer:number；
只返回 JSON。请读取 context，用 apply_changes 写入候选，validate 后返回 revision。

工作流模板

读取当前 workflow 和 run 证据，把步骤调整为 T3 → T1 → T2；
检查 input/output binding；apply_changes 写入候选，validate 后返回 revision。

9. 如何发布

先通过候选 run，再冻结、发布、激活；没有通过 run 时发布按钮应不可用。

顺序点击通过条件
1训练模式 → SMOKE_ONLY → 运行completed；八个 slot 返回 answer:3。
2冻结候选生成不可变 frozen snapshot 和 SHA-256。
3切发布模式候选只读审核。
4发布 SMOKE 快照并激活生成 release-*，固定 Agent/工作流。
5工程模式 → 运行已发布工作流新 publish run，仍是 SMOKE_ONLY、business gate false。

发布隔离

  1. 工程模式运行并记下发布步骤。
  2. 回训练模式改候选，但不重新发布。
  3. 再回工程模式运行；步骤和结果必须仍是发布前版本。

10. 自己点击验证 Agent 和工作流

这套清单就是用户验收脚本。看到不符合预期就停下，记录 run ID 和错误。

A. 空项目边界

  1. 训练模式刷新 Trainer registry 或查看空项目状态。
  2. 确认空项目为 Agent 0、工作流 0。
  3. 确认没有历史 DFT、原理图专家或旧业务产物自动加载。

B. 单 Agent

  1. 训练模式新建/选择 Agent。
  2. 打开 Agent 原生会话，确认 preset 为 agent-trainer。
  3. 发送：1+2等于几，把答案写在JSON里。
  4. 响应必须是 JSON，数字字段 answer 等于 3。
  5. 回白色页面运行，确认 completed、SMOKE_ONLY、businessGatePassed:false。

C. 工作流

  1. 一 Agent 工作流运行，确认一条步骤完成。
  2. 加入第二、第三个 Agent，确认每条步骤完成且顺序一致。
  3. 调整为 T3 → T1 → T2，保存并运行。
  4. 检查编排结果示例 [7,3,5]；每个 smoke child 的 JSON 仍是 answer:3。
  5. 每步必须有 input、output、revision、status 和 handoff。

D. 发布隔离

  1. 冻结候选，发布并激活，工程模式运行一次。
  2. 训练模式修改候选但不发布。
  3. 再次工程运行；发布步骤和结果不能变化。
✓fresh child 缺失、非 JSON 或 answer 不是 3 都失败。
✓所有 smoke 标记 SMOKE_ONLY 和 businessGatePassed:false。
✓发布后工程运行不受未发布候选影响。

验证证据在哪里

用页面显示的实际 ID 替换占位符：

路径用途
Training_Materials/runs/<runId>/framework-run.json训练步骤、输入、输出、状态、scope 和 gate。
Training_Materials/framework/control/bindings/<sessionId>.json原生会话绑定、preset 和目标。
Training_Materials/framework/control/requests/agent-trainer/<request>.json会话请求、变更和校验。
publish/versions/<releaseId>/release.json发布版本和哈希。
publish/runs/<runId>/framework-run.json工程模式回放。
验收证据 JSON当前主动测试汇总。

哈希必须是小写 64 位 SHA-256；不要把截图当唯一证据。

11. 常见问题

页面打不开

刷新 3080 标签页，确认 DSH host 监听 127.0.0.1:3080；旧标签可能停留在重启前错误页。

发布按钮灰色

先完成通过的 run，再冻结；发布模式本来只读。

会话没有 Trainer 工具

必须从白色页面打开 agent-trainer 原生会话。

运行失败

看第一个失败 slot/步骤，检查 JSON、revision、顺序和 preset。

工程模式看不到 Agent

只显示已发布工作流实际绑定的 Agent。

为什么 gate 是 false

这是 SMOKE_ONLY 的正常合同；不要修改 smoke 流程来强行变成 true。

!
结论写法：可以写“模型调用、阶段交接、训练/冻结/发布/工程回放通过”；不能写“半导体业务已通过”。
