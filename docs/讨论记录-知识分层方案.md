## Q1：规则如何分层、单一权威、去重

### 诊断
cbite 连接规则现散落 7 处：rules-registry.md / relay-agent.md / cbit-*.md / hardware/relays.md / 根目录txt / auto-memory nuvola-*.md / verify脚本。根因=按"来源/顺手"存，未按"性质"分层。

### 三层知识模型
| 层 | 是什么 | 唯一家 | 谁改 | 强制 |
|----|--------|--------|------|:---:|
| L0 规范层 | 机台手册/API/datasheet（不可改的事实） | knowledge/sources/ + 原PDF | 人 | 只读引用 |
| L1 规则层 | 约束 agent 生成代码的铁律 | rules-registry.md（唯一正文） | rules-agent→人审 | 强制 |
| L2 经验/子函数 | 非强制绕法 / 可复用代码 | experience/ + shared_functions/ | exp/fn agent | 不强制 |

来源落位：
- 机台手册→"事实"进 sources；"必须遵守否则报错"的约束→进 L1 规则库，来源标「手册§X.Y」，不复制原文。
- 子agent 内嵌规则→拆成"流程步骤(留agent)"+"规则铁律(上收 L1)"。
- 自进化项目通用规则→直接进 L1。

### 去重铁律
一条规则 = 一个 ID = 一个正文位置，其余只引用：
- 正文 → rules-registry.md
- agent .md → 只写流程 + 引用 ID
- 脚本 → 规则 ID ↔ 错误码/RULE_COVERAGE 映射
- auto-memory → 只留指针，不存正文
- 根目录散件 → 归档删除

### 两个知识库分工（隐藏最大重复源）
- 项目知识 `knowledge/`（git版本化、团队共享）= 规则正文的权威家
- auto-memory `nuvola-*.md` = 只存进度指针/非显而易见上下文/跨项目偏好，不复制规则正文

### 输入协议（用户怎么给我规则/资料）
决策树：别人写的规范→sources；强制铁律→L1（能机器判定→同时落 verify 脚本/错误码）；参考绕法→L2经验；可复用代码→shared_functions。

统一模板：`【类型】规则/规范引用/经验/子函数 | 【一句话】 | 【来源】 | 【适用范围】 | 【能否机器判定】 | 【正文】`

### 落地三步（待用户确认）
1. 立规范：写 `knowledge/standards/知识分层规范.md`（或进 CLAUDE.md）
2. 收敛规则正文 → rules-registry.md 唯一家，其余改 ID 引用，删根目录散件
3. 修 auto-memory：nuvola-*.md 降级为指针

## Q2：规模上去之后怎么不失控

### 1. 不遗漏 → 完整性可机检（不靠人记）
- 注册表完整性审计脚本：ID 连续/无重复、必填字段齐全、active 规则有强制层、反向引用检查（agent/脚本引用的 ID 必须能查到）
- 来源清单对照：L0 手册列清单（手册+章节），标"已提炼/未提炼"，未提炼自动高亮
- 单一入口 + 自增 ID，脚本查跳号
- 引用即登记

### 2. 分类 → 多轴标签，不是树
一条规则 = 一行 + 固定标签集：层级 / 领域 / 类别(global·specialized) / 适用范围 / 强制层 / 来源 / 状态
分类谁做：我默认分类 + 每条附一句依据；把握<70% / 落强制层 / 会污染库 才反问。
顶层领域清单（上电/下电/继电器-CBITE/通路/测量/寄存器/Trim/Toggle/命名/单位/批量纪律/编译）我提草案，用户确认一次后冻结，新增领域须登记。

### 3. 导出 review
- `gen_rules_report.py` 导出 Excel（带筛选）+ HTML，列=ID/一句话/类别/适用范围/强制层/状态/来源/依据
- 核心：只看变更（git diff 或 changelog 段），`--changed` 只看改动行 → 人 review → 确认后同步强制层

## Q3：参考材料怎么给 / 存档 / 分类索引

### 核心：材料 vs 规则分开
材料本身进参考层存档，提炼出的铁律才进 L1/L2。

### 分类树（参考层）
```
knowledge/references/
├── code/     代码案例：trim / power-on / high-current / os / burn
├── circuit/  电路设计：current-sense / closed-loop
├── chip/     芯片block&参数：rdson / zcc / uvlo / adc
└── index.md  ★唯一索引
```
`D:\Newtest\CLAUDE_PROCESS\库函数\test_method` 是专项 ramp 库，平级不并入。

### 单一索引 index.md 每条一行
分类 / 名称 / 位置 / 一句话用途 / 对应TM·参数 / 是否已提炼规则

### 输入协议（用户给资料模板）
`【类型】代码案例|电路设计|芯片测试方法|手册 | 【名称】 | 【文件】 | 【对应】TMxx/Rdson... | 【一句话用途】 | 【提炼要求】要抽规则|只要存档|两者`

### 我收到后四步闭环
① 归档（存提炼版模板+关键片段，长文档存指针+摘要不复制全文）→ ② 提炼规则（铁律进 L1 标来源，写法进 L2）→ ③ 更新 index 标"已提炼→R-xx" → ④ 报告存哪+提炼了什么规则。
生成代码时 agent 按测试类型查 index → 找模板+关联规则。

## Q4：sub 函数/库函数怎么用上、管理、更新

### 核心：函数本体 vs 函数注册表分开
- 函数实现：用户维护（D:\Newtest\CLAUDE_PROCESS\库函数\test_method + D:\Newtest\CLAUDE_PROCESS\库函数\shared_functions\src，已有）
- 函数注册表：我维护（签名+语义+触发），缺=用不上的根因

### 单一注册表
`knowledge/standards/functions-registry.md`，每条一行：
函数名 / 库 / 签名 / 触发场景 / 调用语义·坑 / 调用点 / 版本状态

### 用上机制：生成前先查
codegen skill 加"函数库优先检查"：生成 measure/power/ramp 前查注册表，命中→调函数（带正确参数语义），未命中→写裸代码（收尾≥2处重复标记给 sub-function-agent 提炼）。
= 从事后提炼升级为事前复用。

### 更新协议（函数模板）
`【类型】新增|改签名|改语义|弃用 | 【函数名】 | 【库】 | 【签名】 | 【触发场景】 | 【调用语义】 | 【调用点】 | 【影响面】`
我收到后：① 更新注册表 ② 影响面检查（扫已生成代码调用点列出需同步改的 TM）③ 报告。

## 工作流全景（用户梳理版 · 2026-08-15，源：Offline Coding 全景工作流.txt）

### Offline Coding 定义
= Part1 DFT(测试方法) + Part2 原理图(支持100%DFT) + Part3 机台手册规则 + Part4 工程师经验 → 生成可被机台软件编译通过的 VS 工程。不涉及原理图优化，只解析现有原理图连接关系。

### ① 一次性前置（解析一次 → 单一文档，后续只读）
- S1 原理图解析：Component-Map(元器件统计) + 通路梳理(源表→PIN，最短=第一优先级常用，次短=第二优先级备用)
- S2 DFT解析：test-Condition 文件(上电/寄存器/测量条件)，多步骤=条件n→寄存器n→测试n→n+1
- S3 源表+继电器定义：StdAfx.h + test.cpp + Pin_Channel_Define.h（⏳未完成，用户提供）
- S4 Treg文档定义（⏳未完成，用户提供）

### ② 循环体（每测试项目 10 步）
S5 分类(Trim/OS/P2P/ABS/Pre_Read/Burn/Post_Read/ADC/AWG(UVLO)/CurrentSense/RDSON/CloseLoop) → S6 框架(名字按DFT,格式按手册,log参数必须在定义里可少不可多) → S7 变量(TRIM_NODE等) → S8 继电器闭合 → S9 上电 → S10 寄存器(部分配置不在DFT需到指定文件夹找,后续给registermap) → S11 测量(trim=execute+measure, AWG=库函数) → S12 下电 → S13 log → S14 检验

### ③ 规则两分法（对应 Q1 分层）
- 机台规则(手册用法,cbite.SetOn等) = L0 规范层，只读引用
- 项目规则·第一层 闭环原则(必须连哪些继电器) = L1 硬规则
- 项目规则·第二层 工程应用经验(电容接法/量程/clamp/采样点/切量程/大电流恢复0/下电次序/量程统一) = L1+L2 持续沉淀

### Action 清单（= 分工所有权锚点，共 10 处）
1. S1 规则无法满足→记录等更新；2. S2 同；3. S3 机台源表定义+命名规则→安排其他人；4. S4 同→安排其他人；5. S5 参数识别方法+常规做法→用户逐步完善(提供代码案例+芯片Block+DFT总结)；6. S8 cbite用法+工程经验→用户教/更新；7. S9 量程/不过冲/clamp→用户更新；8. S10 机台规则+registermap→用户更新；9. S11 采样/切量程/恢复0/量程转换→用户更新；10. S12 下电经验→用户更新
