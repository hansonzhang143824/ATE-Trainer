# paths.txt 生成规范（平台无关版）

> 用途：从原理图 Netlist 生成"源表 → DUT Pin 通路文档"（paths.txt）。
> 本文档自包含，不依赖任何特定 AI 平台的 agent/skill 机制，可整体作为系统提示词或知识库迁移到豆包、DeepSeek、GPT 等平台，达到同等生成效果。

---

## 一、产物清单：paths.txt 必须包含的内容

paths.txt 是纯文本通路文档，包含 4 个固定章节：

### 1.1 FPVIe 通路（## FPVIe 通路）
- 按 FPVIe 通道分组，标题格式：`### S{槽位}_FPVIe_FHSH{通道号}` 或 `FLSL`
- 每行一条通路，格式：
  ```
    {源标签}/{侧} -> K{编号}(Relay-{状态}) -> K{编号}(Relay-{状态}) -> {DUT Pin基名}  {配对标注}
  ```
- 示例：
  ```
    S1_FPVIe_FHSH0/FH -> K87(Relay-NC), K88(Relay-NC) -> K58(Relay-ON) -> SDA  [Kelvin]
    S1_FPVIe_FLSL0/FL -> K90(Relay-ON) -> VBUS  [PC短接]
  ```
- 配对标注三选一：`[Kelvin]` / `[PC短接]` / `[单线]`（规则见 §四-R7）
- Force 和 Sense 走同一继电器时只显示一次；同位置不同继电器时逗号并列（Force 在前，Sense 在后）

### 1.2 ACM200 通路（## ACM200 通路）
- 每行：`  {源端口} -> K{n}(Relay-{状态}) -> ... -> {DUT Pin基名}`
- 无通路时输出 `  (无通路)`

### 1.3 FOVIe 通路（## FOVIe 通路）
- 格式同 ACM200

### 1.4 继电器状态汇总（## 继电器状态汇总）
- Markdown 表格，列出 Netlist 中出现的所有继电器编号（升序）：

| 继电器 | 功能分类 | 默认状态 | SetOn状态 |
|--------|:---:|:---:|:---:|
| K15 | BUS | Pin↛BUS | Pin↔BUS |
| K20 | Share | 默认通道 | 备用通道 |
| K16 | Cap | Cap断开 | Cap接入 |
| K8 | FPVIe矩阵 | FPVI→BUS | 保持NC |
| K46 | MOS P2P | 断开 | 闭合 |
| K61 | 通用G6K | 视设计 | 视设计 |

### 1.5 输出字段取值约束

| 字段 | 取值 | 含义 |
|------|------|------|
| Relay 状态 | `ON` | 需通电（SetOn）才导通的路径 |
| Relay 状态 | `NC` | 默认（不上电）即导通的路径 |
| 配对标注 | `[Kelvin]` | Force 路径终点为 `_F_Sx`，Sense 路径终点为 `_S_Sx`（4线，DUT 端汇合） |
| 配对标注 | `[PC短接]` | Force 与 Sense 路径终点同为 `_F_Sx`（2线，中途已短接） |
| 配对标注 | `[单线]` | 无配对对象的独立路径 |
| DUT Pin 基名 | 去掉 `_F_Sx`/`_S_Sx`/`_FORCE_Sx`/`_SENSE_Sx`/`_Sx` 后缀 | 合并显示，不区分 F/S |

## 二、输入依赖清单（知识库/数据文件）

| # | 输入 | 格式 | 用途 | 必需性 |
|---|------|------|------|--------|
| D1 | 原理图 Netlist | `.NET`（Allegro/HDL 格式） | 全部通路追踪的数据源 | **必需** |
| D2 | CBIT 表 | `.xlsx/.csv` | ①继电器功能分组（MOS/G6K_DEDICATED/G6K_SHARED）用于纠正类型误判；②继电器编号↔CBIT 位号映射 | 推荐（无则继电器类型全靠引脚数推断，可能误判） |
| D3 | 继电器功能分类表 | 本文 §三-K2 内置 | BUS/Share/Cap/FPVIe矩阵/MOS P2P 分类 | **必需**（已内嵌本文，换板卡需更新） |
| D4 | 稀缺源表清单 | 本文 §三-K1 内置 | 决定谁可以借道 BUS 公共节点 | **必需** |

### Netlist 必须能解析出的三类信息
```
(port (rename "显示名" "原名") (direction OUTPUT|INOUT))   → 端口及方向
(Net "net名" (PortRef &引脚号 (InstanceRef 实例名)) ...)   → 网络及连接
K{数字}_ 开头的 InstanceRef                                → 继电器实例
```

## 三、内置知识库（规则常量）

### K1. 稀缺源表
**FPVIe、QTMU、QVM** 为稀缺源表。只有稀缺源表可以使用 BUS 公共节点；其他源表（ACM200/FOVIe 等）禁止借道 BUS。

### K2. 继电器功能分类（按编号，当前 HIB 板卡）
| 分类 | 编号集合 | 默认 NC 含义 | SetOn NO 含义 | 追踪策略 |
|------|----------|--------------|---------------|----------|
| BUS | 15,17,19,21,26,29,31,33,34,38,40,41,42 | Pin 断开 BUS | Pin 连通 BUS | 只追踪 ON 路径 |
| Share | 20,22,23,35,36 | 通默认通道 | 通备用通道 | 两条都追踪，标注目标通道 |
| Cap | 16,18,25,28,30,32,37,66 | Cap 断开 | Cap 接入 | 只追踪 ON 路径 |
| FPVIe矩阵 | 8~13 | FPVI→FPVI_BUS 直通 | 备用路径 | 保持默认 NC，不追踪 NO，**不进 SetOn 列表** |
| MOS P2P | 46~59, 68 | 断开 | 闭合 | 只追踪 ON 路径 |
| 其余 G6K | 其他编号 | 视设计 | 视设计 | 两条都追踪 |

> ⚠️ 换一块 HIB 板卡时，此表必须从该板卡的 CBIT 表/原理图重新提取。

### K3. 继电器电气模型
| 类型 | 判断方法 | 线圈脚 | 默认 NC 通路 | SetOn NO 通路 |
|------|----------|--------|--------------|----------------|
| G6K-2G-Y（机械8脚） | 连接引脚 max≥5；或 CBIT 表分组为 G6K_* | 1, 8 | 3↔2，6↔7（两组同步） | 3↔4，6↔5（两组同步） |
| MOS（TLP3412 类） | 连接引脚 max∈{3,4} | 1, 2 | 断开 | 3↔4 闭合 |
| MOS2（2脚MOS） | 连接引脚 max=2 | 无（控制端走 CBIT，不在信号网表） | 断开 | 1↔2 闭合 |

- **类型纠正规则**：G6K 若只在 netlist 中暴露 ≤3 个引脚会被误判为 MOS，必须用 CBIT 表分组（G6K_DEDICATED/G6K_SHARED → G6K）覆盖纠正。
- 继电器实例识别：实例名匹配 `K{数字}_`。

### K4. 端口分类
- `direction=OUTPUT` → **DUT Pin**（芯片引脚，即原理图上的 copper，经弹簧针到芯片 PAD）
- `direction=INOUT` → **源表端口**（POGO）
- FPVIe 端口命名：`S{槽位}_FPVIe_{FH|SH|FL|SL}{通道号}`，FH+SH 捆成 High 侧（FHSH），FL+SL 捆成 Low 侧（FLSL）

### K5. BUS 域划分
- HIGH 域关键词：`FH_BUS, SH_BUS, FH_PC, SH_PC`
- LOW 域关键词：`FL_BUS, SL_BUS, FL_PC, SL_PC`
- 源端口域：`_FH/_SH` → HIGH，`_FL/_SL` → LOW

## 四、执行流程与规则（Pipeline）

```
Netlist(.NET) ──→ [P1 解析] ──→ 端口表/网络表/继电器表
CBIT表 ────────→ [P1 解析] ──→ 继电器类型纠正、功能分组
                        ↓
                 [P2 预处理] FPVIe 通道捆扎、源端短接继电器排除
                        ↓
                 [P3 BFS 追踪] 每个源端口 → 各 DUT Pin 最短通路
                        ↓
                 [P4 F/S 配对合并] Kelvin / PC短接 / 单线
                        ↓
                 [P5 格式化输出] paths.txt 四章节
```

### P1 解析规则
- **R1.1** 提取所有 port：名称（rename 优先取显示名）、方向。排除 `UNDEFINED`。
- **R1.2** 提取所有 Net：net 名（`(rename)` 前缀需还原）→ [(实例名， 引脚号)] 列表。
- **R1.3** 收集继电器实例：实例名匹配 `K\d+_`，记录其连接引脚集合，按 K3 判断类型，再用 CBIT 表纠正。
- **R1.4** 构建反查表：实例+引脚 → 所属 net 列表。

### P2 预处理规则
- **R2.1 源端短接继电器排除**：2 脚继电器，其所有连接 net 全是 INOUT 源端口（如 K86/K130：FH↔SH 内部短接）→ 视为仪器内部走线，**不参与路径**。例外：涉及 AGND/GND 的保留。
- **R2.2 FPVIe 通道捆扎**：按 (槽位， 通道号） 分组，FH+SH→`S{x}_FPVIe_FHSH{n}`，FL+SL→`S{x}_FPVIe_FLSL{n}`；单侧存在则单独成组。

### P3 BFS 追踪规则（核心）
对每个源端口做 BFS，状态 = (当前net, 路径， 已访问继电器集合， 已进入的BUS域)，每个 DUT Pin 只保留**继电器数最少**的一条：

- **R3.1 深度限制**：最多穿越 4~6 个不同继电器（max_depth），防无限搜索。同一继电器编号不重复穿越。
- **R3.2 线圈脚不可穿越**：经过继电器时从信号脚进、按 K3 通断表出，线圈脚跳过。
- **R3.3 双状态尝试**：每个继电器分别尝试 NC 和 ON 两种穿越；FPVIe 矩阵继电器（K4 分类）只允许 NC。
- **R3.4 稀缺源表约束**：非稀缺源表（ACM200/FOVIe 等）的路径**禁止进入任何 BUS 公共节点**（K5 关键词匹配的 net）。
- **R3.5 FPVIe 域约束（铁律）**：HIGH 侧源（FH/SH）禁止进入 LOW 域 BUS 网，反之亦然。FH 必须配对 SH、FL 必须配对 SL，禁止交叉。
- **R3.6 跨域 BUS 短接禁令**：一条路径中不允许两个 ON 继电器分别接入不同 BUS 域（会把两个公共节点短接）。
- **R3.7 终点判定**：到达的 net 是 DUT Pin（OUTPUT 端口）且路径非空 → 记录一条通路。
- **R3.8 DUT Pin 无同名 net 的三步查找**（短路 Pin 场景）：
  - Step A：Pin 名直接匹配 net 名；
  - Step B：找不到则在所有 net 中搜索"继电器实例名包含该 Pin 名"的连接（如 `K101_BUS_PA0_S1` 含 PA0），取关联最多的 net 作为该 Pin 的信号 net（适用于两 Pin 电气短接场景，短接判定：<10Ω 电阻或导线直连，合并命名 `PIN1_PIN2`）；
  - Step C：都没有 → 该 Pin 无通路，跳过。
- **R3.9 中间源表标注**：路径若途经其他源表端口（如 ACM200），记录 `intermediate_source`，供下游命名区分。

### P4 Force/Sense 配对合并规则
- **R7.1** 追踪阶段保留完整 Pin 名（含 `_F_Sx`/`_S_Sx` 后缀），合并阶段才按后缀配对。
- **R7.2** 后缀解析：`VBUS_F_S1→(VBUS,F)`；`VBUS_S_S1→(VBUS,S)`；`nRST_S1→(nRST,'')`（无 F/S 的归入 Force 侧）。
- **R7.3 两轮配对（顺序不可换）**：
  - Pass 1 **[Kelvin]**：Force 侧终点 `_F` + Sense 侧终点 `_S`，按"同位置同继电器同状态"重叠数最大者配对；
  - Pass 2 **[PC短接]**：Force 侧终点 `_F` + Sense 侧终点同为 `_F`，同样按最大重叠配对；
  - 剩余未配对 → **[单线]**。
- **R7.4 交错显示**：配对成功的两行合并为一行，逐级比较——同位置同继电器同状态显示一次，不同则 `K46(Relay-ON), K49(Relay-ON)` 逗号并列（Force 在前）。
- **R7.5** 终点显示合并基名（去后缀），不显示 (F)/(S) 标注。同一 Pin 存在多条起止相同的通路时的区分后缀（H/L → 途经源表 → A/B/C）属于下游 #define 命名阶段，不影响 paths.txt。

### P5 格式化规则
- **R8.1** 继电器步进格式：`K{编号}(Relay-{ON|NC})`，编号取实例名中 `K` 后的数字（去 `_Sx` 站点后缀）。
- **R8.2** FPVIe 行首：`{通道标签}/{FH|SH|FL|SL}`；其他源表行首：源端口全名。
- **R8.3** 章节顺序固定：FPVIe → ACM200 → FOVIe → 继电器状态汇总。
- **R8.4** 继电器状态汇总表覆盖 netlist 中出现的全部继电器编号，状态语义按 K2 分类填写。

## 五、质量检查清单（生成后自检）

| # | 检查项 | 失败表现 |
|---|--------|----------|
| C1 | 每条通路两端是否分别为源端口和 DUT Pin？ | 出现 net 到 net 的无端点路径 |
| C2 | 非稀缺源表路径是否借道了 BUS 公共节点？ | ACM200 路径中出现 FH_BUS 等网名 → 违反 R3.4 |
| C3 | HIGH/LOW 域是否交叉？ | FH 源路径进入 FL_BUS → 违反 R3.5 |
| C4 | 是否存在跨域 BUS 短接路径？ | 一条路径两个 ON 继电器分别接 HIGH/LOW BUS → 违反 R3.6 |
| C5 | FPVIe 矩阵继电器是否被标成 ON？ | K8~K13 出现 Relay-ON → 违反 R3.3 |
| C6 | 源端短接继电器是否混入路径？ | K86/K130 类出现在路径中 → 违反 R2.1 |
| C7 | Kelvin Pin（同时有 _F 和 _S 变体）是否完成配对标注？ | 该标 [Kelvin] 的标成 [单线] |
| C8 | 配对是否遵循先 Kelvin 后 PC短接？ | 顺序颠倒导致错配 |
| C9 | 继电器类型是否与 CBIT 表一致？ | G6K 被当 MOS，通断脚位错误 |
| C10 | 继电器状态汇总表是否覆盖全部编号？ | 漏编号 |
| C11 | Force/Sense 是否都连通？ | 只有 Force 通路没有 Sense 通路（铁律：F 和 S 都必须连通，区别仅在汇合位置 PAD vs Copper） |
| C12 | 短路 Pin（<10Ω 直连）是否合并命名？ | 短接的两个 Pin 各自追踪出矛盾路径 |

## 七、平台迁移要点（给豆包等平台的使用者）

1. **本文 §一~§六 全部内容作为一个知识单元整体提供**，不要拆分投喂——P3 的约束依赖 K1~K5，P4 依赖 P3 的输出格式。
2. **换板卡只需替换三处**：D1 Netlist、D2 CBIT 表、K2 继电器编号分类表；流程与规则不变。
3. **大 Netlist 超上下文时的降级方案**：先用任意脚本/正则完成 P1（解析成"端口表+net连接表"纯文本），再把解析结果交给模型做 P3~P5。解析是机械工作，追踪和配对才是需要推理的部分。
4. **无代码执行环境时**：模型可按 P3 手工模拟 BFS，但必须逐条声明每步经过的继电器及状态（NC/ON），以便人工核对 C1~C12。
5. **同名 net 合并规则**：不同名字的 net 若被 <10Ω 电阻/导线直连，视为同一电气节点合并命名——这是 R3.8 和 C12 的依据，迁移时必须保留。
6. 铁律复述（任何平台都不得违反）：只追踪电气联通路径；不跳继电器；F 和 S 都必须连通；稀缺源表才能用 BUS；HIGH/LOW 域不交叉；不确定的路径标记并继续，不得虚构。
