三、问题清单（讲人话）

问题① 你要的 5 个 TM 里，TM107 压根不在测试规范表里

最要紧需要你决定 证据：工作簿 OVERVIEW 页
发生了什么 测试规范表（唯一权威来源）里一共 20 行条目，编号是： TM000, TM000_1, TM001, TM101, TM102, TM103, TM104, TM105, TM106, TM108, TM109, TM110, TM133, TM134, TM135, TM422, TM424, TM425, TM600, TM601。 中间没有 TM107。TM106 / TM108 / TM109 / TM110 各恰好 1 行，TM107 是 0 行。
为什么这是硬伤 流程规则明写：DFT 条目的匹配数必须是"恰好 1 行"，0 行或多行都必须报"卡住"， 而且禁止拿别的 TM 的行来顶替。没有规范行 = 没有测试条件 = 无法生成代码。
但有个反转 你的实际代码里存在 DUT_API int TM107_HSKP_VBUS_HT_VBAT 这个函数， 说明现实里 TM107 是有东西的——只是它没被写进这张规范表。所以大概率是规范表漏行， 或者你给的范围写错了。
需要你定 TM107 怎么处理？① 规范表漏了，你补进去，我再重跑；② TM107 不在本次范围，本次只做 106/108/109/110； ③ TM107 其实是别的条目名，你指给我。

新发现 · 影响后面所有 TM需要你决定
