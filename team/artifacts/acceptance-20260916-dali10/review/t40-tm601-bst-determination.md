**(1) 决定性：契约自己把本项引脚写出来了** —— `setup-contract.json` → `aliasResolution[bst2sw].resolution.relayChain`（**逐字**）：

```
{ "relay": "K61_ACM8_SW",    "number": 61,  "state": "SetOn (ACM200 S5_FH8  -> SW)"  }
```
⇒ **契约明文本项走 `ACM200 S5_FH18 → BST` 与 `ACM200 S5_FH8 → SW`**（**FH18/SH18 + FH8**，**不是 FH5/SH5**）。
⇒ **判定建立在 (b)：基线用 pin 18（BST 侧）/ pin 8（SW 侧）**。locator：上述 `relayChain` 两条 + `closedRelayNumbers=[110,61]` + IR `S5_ACM200_FH18->BST_F_S1 requiredOnRelays=[110]`。

**(2) 独立机制：`_5` 是通道索引、不是引脚号**（`Pin_Channel_define.h`）—— 该文件 ACM 段宏**严格递增 0..23**（我逐条实测，共 24 条）：`idx4 BST12_U1PS_ACM`(L19)、`idx5 SW12_U1REF_BST_ACM`(L20)、`idx8 VCP_SW_ACM`(L23)、`idx18 PB0_BST_ACM`(L33)；且 `test.cpp` 把**功能名**与宏一一绑定（`ACM200 SW12_U1REF_BST_ACM(_PIN_CHANNEL_DEFINE_SW12_U1REF_BST_ACM_, "SW12_U1REF_BST_ACM");`）。
⇒ **`_5` 是该仪器通道块内的序位，不是引脚号** —— **"基线用 pin 5"混淆了"通道索引"与"引脚号"，这正是 (a) 的成因。**
**旁证（继电器后缀＝通道号）**：`K48_ACM5_AMP_REF`（通道 5）、`K61_ACM8_SW`（**通道 8**）、**`K110_ACM18_BST`（通道 18）**；`K61_ACM8` 恰对应 `idx8 = VCP_SW_ACM`（SW 族），**与 `relayChain` 的 `S5_FH8 -> SW` 自洽**。

**(3) `[48,76]` 那一路属另一通道，且与 `K110` 路**并行**（两路均可达 BST、互不排斥）**
- `SCH:672-674`：`BST 需闭合: K48,K76` / `F: S5_ACM200_FH5 -> K48(ON) -> K76(ON) -> BST_F` ⇒ **`[48,76]` 的源是 ACM200 的 `FH5/SH5`**（`StdAfx.h:620 K_BST_ACM 48,76 // ACM200[] -> BST: K48_ACM5_AMP_REF + K76`）。
- **网表证实两路并行接同一 BST 节点**（我实测）：`K48` 的 ACM 侧在 `NetK46_BUS_FH_SW1_S1_2`（含 `S5_ACM200_FH5`）；**`K76.S1.5` 与 `K110.S1.5` 同在 `NetK57_CAP_BST_SW_S1S2_3 ∋ BST_F_S1`**；**`K76.S1.4` 与 `K110.S1.4` 同在 `NetK76_ACM_BST_S1_4 ∋ BST_S_S1`**。
- **副作用评估**：**即使该分歧判错，也不会导致"BST 不可达"**（两路并行）；**但表述必须正确**，否则读者会误以为"K110 非必需"而将其删除（**本轮已有一名队友如此**）。

**(4) 结论**：**(a) 不成立；(b) 成立** ⇒ `[110,61]` 有效、**K110 必需**、**t29 闭 `K109`+`K110` 合规（依约保守）**。
**对 `t29`/`t40` verdict 的前提注解（照 Captain 要求补）**：**两者以 (b) 为前提**，该前提由 **契约 `relayChain` 明文引脚 + `Pin_Channel_define` 的 0..23 序位 + 继电器通道命名** 三条证据支撑 ⇒ **属有据判定，非"默认采用 (b)"**。
**残余不确定性（如实标注）**：`_n` 与**仪器物理引脚号**的精确对应，我未能从 C 头文件单方证明（**属 `t42` 范围**）；**但本判定不依赖它** —— (1) 已直接写出引脚，(2) 只需证明 `_5` 非引脚号即可排除 (a)。
