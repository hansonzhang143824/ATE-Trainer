# 训练与发布通俗讲义（TRAINING-AND-PUBLISH-GUIDE）

> 面板地址：http://127.0.0.1:4090/ （桥接服务：`node tools\expert-console.mjs`）
> 适用对象：不写代码、只提需求和判断结果的使用者。

## 一、这套东西是干嘛的

8 个专家角色（DFT_Expert、Schematic_Expert、Strategic_Expert、Method_Expert、Review_Expert、Implement_Expert、Compile_Expert、Evolution_Expert）各自有一份"脑子"，由四个文件组成：

| 文件 | 通俗理解 |
|---|---|
| `instructions.md` | 行为规则——遇到 X 该怎么做 |
| `profile.yaml` | 边界——能读哪些目录、能写哪些目录 |
| `cases/<TM>/` | 金标准——历史上做对的案例断言 |
| `output-contract.schema.json` | 交货合同——产物必须长什么样 |

"训练" = 往这些文件里补知识；"发布" = 把草稿定稿成新版本（v1→v2），发布后不可改。

## 二、怎么训练（推荐路径：对话式）

1. **选目标（可选）**：点左侧某个专家 = 设为训练目标；不选也行，Trainer 会自己判断材料属于谁。
2. **喂料**：把流程图文字、领域知识、执行问题、吐槽，原文丢进聊天框（Ctrl+Enter 发送）。不用整理格式。
3. **等回复**：Trainer（AI 训练师）会把材料拆成一条条提案，格式固定：
   `[编号] (专家 | 落盘位置 | 形式) 内容 —— 依据`
4. **勾选执行**：回复到达后，右侧自动出现提案卡片，勾选要采纳的 → 点「✅ 写入选中提案」：
   - 落盘位置是 `instructions.md` 的 → 自动写入草稿 + 立即跑评估；
   - 其他落盘位置（profile.yaml / cases / schema / scripts）→ 暂存到 `team/artifacts/training-proposals.md`，等人工或后续版本执行；
   - 重复提交同一条 → 自动去重（幂等），不会写两遍。
5. **快捷写入**（绕过 Trainer）：如果规则文本你已经想好了，直接用右侧「快捷写入」表单填 专家 + 规则 + 出处，一步落盘。

## 三、怎么发布

1. 切到「📦 发布」页签，选专家（或直接点左侧专家）。
2. 看**版本时间线**：draft 有变更会标黄"待评估/发布"。
3. 点「🧪 评估草稿」：跑 227 项检查，verdict=pass 才值得发布。
4. 点「📦 发布下一版」：自动算版本号（v+1），发布后该版本冻结，改动进新 draft。
5. 「⟳ Roster 校验」：全队一致性体检，应显示 complete。

## 四、典型场景对照

| 你遇到的事 | 该怎么做 |
|---|---|
| 跑批次发现某专家行为不对 | 纠错页签找到对应问题 → 「转训练提案」→ 发送 → 勾选卡片执行 |
| 学到一个新的领域规则 | 直接聊天框喂给 Trainer，或快捷写入 |
| 想让某专家多读/多写某个目录 | 喂料时说清楚 → 提案会标 profile.yaml → 落暂存，人工改边界 |
| 对外要交付稳定版本 | 先评估 pass，再发布；发布记录进 CHANGELOG.md |

## 五、注意事项

- 聊天记录刷新页面会清空，但 DSH 侧 Trainer 会话上下文不丢（sessionId 已落盘 `.trainer-session.json`）。
- 训练写入的是 **draft**；不发布就不会影响正式流程。
- 提案里标"待确认"的条目，先弄清再采纳，Trainer 不编造但也可能判断错。
