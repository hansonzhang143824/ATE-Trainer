## 3. 接口假设（对齐服务端实际契约）

客户端假定同源 `GET /api/ptc-control/state` 返回 `lib/control-state.js#buildControlState` 的 schemaVersion 1 形状：

```json
{
  "schemaVersion": 1,
  "identity": "unbound",
  "activeRelease": { "releaseId": null, "manifestDigest": null, "activatedAt": null },
  "trainingRuns": [ { "runId": "", "mode": "", "status": "", "target": null, "updatedAt": "" } ],
  "delivery": { "batchId": "", "state": null, "releaseId": null, "executionScope": null, "updatedAt": "" },
  "profiles": [ { "profileId": "", "publishedVersion": null, "manifestDigest": null, "draftVerdict": null } ],
  "migration": { "legacyConsoleAbandoned": true, "legacyMode": null, "legacyModeAuthoritative": false }
}
```

契约要点与修正历史：

- `activeRelease.manifestDigest`（非 manifestHash），含 `activatedAt`；可为 null。
- `trainingRuns[]` 项为 `runId/mode/status/target/updatedAt`。
- `delivery` 是**单对象或 null**（非数组 productionBatches）；保留 profiles 与 migration 顶层字段（客户端已归一化保存，UI 暂只显示必显四项，profiles 预留给后续视图）。
- `trainingRuns[].target` 来自运行目录 `state.json`，是对象或 null：`{kind:"profile",profileId}` / `{kind:"pipeline",fromStage,toStage,stages[]}`；客户端保留对象形状并格式化为 profileId 或阶段范围，兼容字符串兜底。
- `identity` 当前恒为 `"unbound"`（模式属于不可变 run context，不属于进程级状态响应）；客户端照实显示，不自行推断。
- 所有字段缺失/类型异常均零抛错降级（"—"/null/空数组），HTTP 非 2xx 进入错误条显示。

## 5. 未决问题

1. **React 渲染验证缺口**：panel.js 未做任何 DOM/SSR 渲染断言，需 Codex 集成后在 DSH web 客户端（或带 react-dom 的构建管线）中验证。
2. **包入口与构建未接线**：`package.json` 仍只导出 `lib/index.js`；后续需由集成方添加 `dsh.client.inject`（至少 `slots`、`locale`，参考 agent-teams 还注入 runtime/conversation/layout 等）与 client 打包入口（tsdown/`window.__ModuleLoader__` 工厂包裹）。本次按文件所有权不越界修改。
3. **profiles / migration 未上 UI**：契约已归一化保存，但当前 UI 只显示必显四项 + 训练/正式两视图骨架；profiles 列表视图留给后续任务。
4. **shell.overlay 唯一性**：本机探查确认客户端 slots 中实际使用的挂载点仅 `shell.overlay`（与 agent-teams 相同）。控制面最终形态若需要独立侧栏/路由入口（如独立 PTC 页签），需要宿主提供更多 slot 名称——属架构决策，未扩大范围。
5. **t 函数签名假设**：Panel 通过 `({ t })` props 接收翻译函数（与 agent-teams slot 面板一致）；实际宿主注入的 t 行为需在真机集成时确认。
6. **轮询节奏**：默认 5s 轮询为骨架取值；agent-teams 用 1s（活跃）/5s（探测）双档。后续接入运行控制时再定节奏。
