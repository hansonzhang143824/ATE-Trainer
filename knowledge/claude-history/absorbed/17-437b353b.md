## 会话脉络

1. **用户贴出**：CH0 High→VBAT 路径 `S1_FPVIe_FH0 -> K87(NC) -> K143(ON) -> K144(ON) -> K7(ON) -> K8(NC) -> VBAT_F`（及 SH 侧），问是否最短。
2. **侦察**：网表 DLP 加密需 python 读；K143 = `FPVIe0_FH_BUS_S1`↔`S24_P5`、K144 = `FPVIe1_FH_BUS_S1`↔`S24_P5` —— 两通道总线间的**桥**。
3. **关键反例排除（K141 假捷径）**：K141 引脚 `pin2=FPVIe1_FH_BUS, pin3=S10_CH0_A, pin4=FPVIe0_FH_BUS`；NC = FPVIe1_FH_BUS↔S10_CH0_A、ON = S10_CH0_A↔FPVIe0_FH_BUS —— 是 **QTMU 源选择开关**，两个状态都夹着 S10_CH0_A，**任何状态都不存在 FPVIe0↔FPVIe1 直连**。初判"有更短路"错误。
4. **BFS 验证脚本修正**：初版漏 CBIT 类型覆盖（3-pin G6K K87/K141 的 ON 态判定）→ 补 CBIT override 后 BFS 与 SCH-Connect-Map **逐条一致**。
5. **穷举结论**（深度≤7 所有简单通路）：FH0→VBAT_F 仅 2 条（Map 5 跳为最短；另一条 7 跳绕路 K87→K141→K66→K64→K62→K7→K8）；SH0→VBAT_S 仅 1 条且即 Map 所选。`需闭合 K136,K137,K143,K144,K7` = 两路径 ON 继电器**并集，一个不多**。

## 关键结论（拓扑知识，沉淀候选）

- **为什么 CH0 看起来绕**：CH1/QVM 的 VBAT 继电器组（K7/K8）本就挂在 **FPVIe1 总线**（CH1→VBAT 只要 K7，QVM→VBAT 只要 K136+K7）；**CH0 是 FPVIe0 总线**，与 VBAT 不同总线域，必须过桥。两通道总线间无单继电器直连桥，只有两对桥：FH 侧 `FPVIe0_FH_BUS─K143(ON)─S24_P5─K144(ON)─FPVIe1_FH_BUS`、SH 侧 `FPVIe0_SH_BUS─K137(ON)─S8_QVM_CH0+─K136(ON)─FPVIe1_SH_BUS` → CH0 天然比 CH1 多一对桥（+2 继电器），是**电路拓扑决定**，非搜索算法漏短。
- 路径行 `(Relay-NC)/(Relay-ON)` 的 ON 判定依赖 **CBIT 表类型覆盖**（G6K 3-pin 状态机），验证脚本必须带。
