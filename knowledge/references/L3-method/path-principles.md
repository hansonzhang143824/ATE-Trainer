# 找通路三原则（2026-08-30 用户权威，每次找通路的第一原则）

> 使用方：relay-agent（Step 1/2 通路继电器）、gen_source_path.py（规划门）、任何源表选择。
> 关联：`relay-checklist.md`（继电器清单）、`hardware/bus-topology.md`、memory [[nuvolta-path-principles]]。

① **精度第一 — 是"门"不是"筛"**：DFT 没特殊强调精度时，ACM200/FOVIe/FXVIe/FXVIe_PLUS/FPVIe 精度**全部满足** → 精度不淘汰任何驱动源，决策直接落 ②。只有 DFT 点名特殊精度（DSL `!` 前缀）才收窄到精密源 {FPVIe, ACM200}。能力硬约束是**另一层**（与精度门无关）：hc≥200mA / 真差分两点 / fv>40V → 锁定 FPVIe；真差分需浮动源 FPVIe 单通道或 ACM200 跨单元。

② **最短通路**：精度门内选闭合继电器最少。SCH-Connect-Map 列2/6/7 每条路径的 `需闭合:` 继电器清单，**按继电器并集数升序**取最短；最短被占 → 第二短兜底。

> **实测排名（2026-08-30，SCH-Connect-Map 解析）**
> - VBAT：FXVIe_PLUS ch5 (K8 默认导通=0) < FPVIe CH1 (K7=1) < FPVIe CH0 (5)
> - BST：ACM200 ch5 (K48+K76=2) < FPVIe CH0 (K46+K48+K76=3) < FPVIe CH1 (4)
> - VCP_SW：ACM200 ch8 (K61 NC=0) < FPVIe CH0 (K68,K87,K88,K90,K91=5)
> - BST-SW 差分：FPVIe ch0 (K46,K48,K76,K60,K61=5 并集) < FPVIe ch1 (5)
> - TM641 复现：diff BST-SW→FPVIe ch0(K46+48+76+K60+61=5) + VCP_SW→ACM200 ch8(0)，与真实编译代码逐继电器一致。

②' **Pin2Pin 特殊规则**：需求涉及 **Pin2Pin 电压或电流** 时，有可用 FPVIe 单通道浮动跨两点（H→pinA + L→pinB），**算作最短通路，优先级高于拆两个独立源表单端**（即使每端各自都是最短通路/0继电器）。真差分语义 > 单端各自最短之和。TM641 方案B 即此例（FPVI0 跨 BST-SW，不用"两源驱动再软件扣偏置"绕路）。DSL：`diff:pinA-pinB`（电压）/ `fi:pinA-pinB,<A>`（电流）。

③ **并行效率**：非必要不串行执行，多用不同源并行。**落地 = 跨需求继电器重叠检测 + 自动避让（v2.1）**：
- 同一继电器被 ≥2 需求需闭合 → 需求 pin 集**相交**（落同一节点）= 良性共用可并行（TM641 先例 FPVI0 Low 与 ACM200 共用 K61 到 SW）→ `[继电器共用]` 信息
- 需求 pin 集**不相交**（落不同节点）= 继电器冲突（短接两路/需串行）→ **自动换第二短通路避让**：成功 → `[继电器避让]`✓ 不阻塞；第二短也撞 → `[继电器冲突·残留]`⚠ 需串行，不阻塞
- **冲突降级原则（2026-08-30 用户拍板）**：**只要本电路可以满足的（①借第二通路 ②不用浮动源/拆两独立源表）都不需人工裁决；只有"缺失无法满足"才 ✗ 阻塞裁决**。缺失 = 超量程（hc>10A / fv>100V）+ Pin2Pin 两端无任何驱动源
- FPVIe 满 → 自动 ACM200 跨单元 / 自动拆两独立源表单端（非浮动，需软件差分/扣偏置）→ `[自动降级/拆源表]`✓ 不阻塞
- hc 通道满 / >40V 满 / ≥200mA 满 → ⚠ 串行提示（分时可满足），不阻塞

## 单端对地驱动排除 FPVIe

地图 CH0/CH1 Low→AGND 标"非有效通路" → **FPVIe 不做单端对地驱动**。VBAT 单端斜坡（BUBO 阈值）不占 FPVIe → FXVIe_PLUS（用户纠正：上电不需要用到 FPVI）。

## 遍历范围边界（执行时不穷举全网表）

找通路只遍历**该 PIN 在地图列2/6/7 收录的行**（`PATH_COSTS[pin]`），**不是"全网表所有源表→PIN 通路"**。逐层收窄：

1. **能力白名单**（先锁源表类型，再列通路）：hc→FPVIe；真差分→FPVIe/ACM200；单端对地→排除 FPVIe；fv>40V / fi≥200mA→FPVIe（`REQ_RULES`）
2. **精度门**（仅 DFT 点名精度才收窄 {FPVIe,ACM200}，否则全驱动源过）
3. **最短/第二短**：白名单内按需闭合继电器数升序取首位/次位（`drive_paths`）
4. **跨需求重叠检测**：只扫**已选中需求**的继电器集（`avoid_relay_conflicts` 预计算 + 仅被换路那条增量重算）

**四层收窄流程图**（执行时依次下钻，任一层的候选被淘汰即不进入下一层）：

```text
需求 DSL (fv / hc / diff / fi / meas / pw)
   │
   ▼
① 能力白名单 REQ_RULES ── 先锁源表类型，再列通路
   │  hc≥200mA / fv>40V / fi≥200mA → FPVIe
   │  真差分(两点都非地) → FPVIe / ACM200
   │  单端对地 → 排除 FPVIe
   │  只遍历 PATH_COSTS[pin] 收录的行（不枚举全网表再筛）
   ▼
② 精度门（"门"不是"筛"）
   │  DFT 点名特殊精度（DSL `!` 前缀）→ 收窄 {FPVIe, ACM200}
   │  未点名精度 → 全部驱动源通过
   ▼
③ 最短 / 第二短  drive_paths（lru 缓存）
   │  白名单内按需闭合继电器数升序
   │  第1位 = 最短 · 第2位 = 冲突兜底
   ▼
④ 跨需求重叠检测  avoid_relay_conflicts（预计算继电器集 + 仅换路增量重算）
   │  只扫已选中需求
   │  pin集相交 → [继电器共用] ✓ 并行（TM641 K61 先例）
   │  不相交 → 换第二短避让
   │        ├─ 成功 → [继电器避让] ✓ 不阻塞
   │        └─ 又撞 → [继电器冲突·残留] ⚠ 串行，不阻塞
   │  缺失(超量程 hc>10A/fv>100V · Pin2Pin 两端无源) → ✗ 阻塞裁决
   ▼
规划输出: 源表 + 通道 + 需闭合继电器清单 + FPVIe预算 + [共用/避让/残留/降级] 标注
   ▼
relay-agent 直接消费规划输出 → 不做二次穷举（穷举法仅无规划输出时人工兜底）
```

脚本已实现（`gen_source_path.py`：`ranked_paths`/`diff_paths` lru 缓存 + `drive_paths` 源表白名单枚举，单次规划 <0.1ms）。**relay-agent 有规划输出就直接消费（源表+通道+继电器），不做二次全量穷举**；穷举法仅规划不可用时兜底。

## 工具

`gen_source_path.py`（工程根，规划门）：需求 DSL → 能力 → 冲突。`!` 前缀=DFT点名精度；`diff:pinA-pinB[,vrng]` / `fi:pinA-pinB,<A>` / `fv:pin,<V>` / `hc:<A>,pin` / `pw:pin,<V>` / `meas:pin`。输出源表+通道+继电器清单+最短/第二短+FPVIe 预算+`[继电器共用]/[继电器避让]/[继电器冲突·残留]/[自动降级/拆源表]`。自检 `python gen_source_path.py --demo`（12 demo 全绿：TM641 0 冲突0避让0残留）。
