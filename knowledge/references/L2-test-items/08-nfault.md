# 模块 08：故障报告 nFAULT（Fault Output）

> 初稿（待用户校验）：领域知识整理。用于故障观测/响应类测试（nFAULT、DTEST0、DMUX 观测脚）。
> ⏳ **待用户修改校验**。

## 1. 功能

**nFAULT**：芯片的故障指示输出引脚。当内部检测到故障（UVLO/OCP/OVP/TSD 等）时**拉低**，通知系统控制器。
是**数字观测脚**——ATE 测试通过监测其电平翻转来判断保护是否触发。
> ⚠️ **nFAULT 是功能代称**：不同芯片/项目的实际观测 PIN 不同（DTEST0 / DMUX / 各项目专有脚），须按项目解析。

## 2. 硬件结构（故障集 & 输出特性）

- **故障事件**：UVLO、OCP、OVP、TSD（过温）、BST_UV 等触发 → 置位
- **输出类型**：Open-Drain（开漏）或 Push-Pull
  - **Open-Drain**：需**上拉电阻**（如 K_xx_PU 继电器）才能读到高电平；低电平=故障
  - **Push-Pull**：直接驱动高低，无需上拉
- **锁存/自动恢复**：部分故障锁存（需复位），部分自动恢复（故障消失即清除）
- **去抖/抗干扰**：部分故障有 deglitch（如 t_BST_UV_DG）

## 3. ATE 测试方法（通用）

- **观测配置**：确认观测脚是 nFAULT 的哪个 PIN + 是否需上拉（Open-Drain 加 K_PU）
- **建立正常态**：让芯片工作正常，观测脚应处高电平（无故障）
- **触发故障**：施加故障条件（如扫到 UVLO/OCP 阈值）→ 观测脚翻转（高→低）
- **恢复**：故障消失 → 观测脚回高（或需复位）
- **观测**：数字比较器监测观测脚电平翻转瞬间（同步锁存当前施加值 = 阈值）

## 4. 派生知识（可推导的测试要求）

| 想问/要测 | 推导 |
|---|---|
| **观测脚怎么配置** | 查 nFAULT 功能代称 → 实际 PIN；Open-Drain 需加 K_PU 上拉 |
| **故障是否触发** | 施加故障条件 → 观测脚由高翻低 |
| **是否需要复位** | 看故障是否锁存（锁存需复位才恢复） |
| **去抖时间** | 故障需维持超过去抖才触发 → 扫描别太快 |

## 5. 易错点

- ❌ 用错观测脚（nFAULT 是代称，实际 PIN 不同）→ 观测不到翻转
- ❌ Open-Drain 忘加上拉 → 观测脚读不到高电平（恒低假故障）
- ✅ 观测脚与 ramp 方向约定（TM641/643）：升扫 TRIG_FALLING 捕 rise / 降扫 TRIG_RISING 捕 fall

## 6. 实例引用

- TM1205（DMUX 57/58 观测）
- golden toggle-template（Toggle 双扫观测）
